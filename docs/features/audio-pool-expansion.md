# 音频池扩容

“设置 → 功能 → 音频池扩容”默认关闭，仅用于战锤3。原版事件／对象音频池的正常预算为39 MiB，另一条初始化路径为64 MiB。联机的大量音频资源可能耗尽这部分容量，出现全局无声。开启后将其启动预算固定为512 MiB，其他子池仍为400、6、12 MiB，总区域930 MiB。

保存设置后完全退出游戏，再从本启动器启动。正常启动、继续游戏、指定存档、联机模式和MOD诊断试启动均使用此选项；各联机玩家分别在本机开启。功能增加容量，不回收已经使用的音频对象，不承诺解决所有失声原因。

## 启动方式

实现为 `backend/audio_pool.py`，由 `backend/launcher.py` 调用。启动器创建主线程挂起的子进程，校验磁盘EXE完整SHA-256、映射后的PE身份、32字节指令锚点及未初始化状态，再只在进程内写入六字节预算指令，回读、恢复内存保护并刷新指令缓存，最后恢复主线程。保留子进程句柄供原退出监控使用。

不创建、改名或替换 `dinput8.dll`，不注入其他DLL，不修改磁盘EXE、存档或MOD Pack。只访问本次创建的子进程；任何版本、签名或写入校验失败都会终止该挂起子进程并返回明确错误，不会静默以未扩容状态启动。校验与创建期间对EXE持有禁止写入、替换的只读句柄。

当前严格支持 WH3 `9.0.5.0`：EXE SHA-256 `d2a8a58288bf8bd86768f21ff6be036cebb1916f9c312999c60afc1abe13789f`，237842896字节，映像大小 `0xe53a000`，时间戳 `0x6ae2a00b`。锚点RVA `0x5a16ca`，补丁RVA `0x5a16cf`，六字节 `b80000002090`；容量512 MiB是固定赋值，不做累计加法。游戏更新后必须核对新版本，不能只放宽哈希限制。

## 与爬塔备用扩容并存

爬塔MOD继续保留原有自动部署与 `dinput8.dll` 早期扩容，供非本启动器启动的玩家使用。它不是启动器功能的前置依赖。两者使用相同预算、锚点和补丁字节；启动器遇到相同补丁返回 `already_patched`，代理也识别相同补丁而跳过写入。

爬塔助手 `audio-bootstrap-2 / launcher-dedup-1` 在公共入口准备时只检查一次补丁、实际容量与内存区域布局。若512 MiB已生效，返回 `already_expanded / pool512_active` 并跳过代理部署，不创建启用标记或安装记录，也不接触外来DLL。未扩容时沿用原有备用部署。已存在的爬塔代理保留，不因启动器设置被删除或覆盖。没有恢复占用采样、计时器或HUD。

## 离线验证

- `tests/test_audio_pool.py`：开关持久化、原始／已扩容状态、32字节逐项破坏、初始化后拒绝、错误EXE、写后回读、失败清理、存档参数与退出监控。
- Windows独立夹具复制Python解释器到 `audio_pool_fixture.exe`，在挂起状态修改无运行用途的DOS头区域，程序入口回读结果；验证Unicode路径、参数、环境、PID、退出码和磁盘文件不变。此夹具从不执行游戏。
- `tests/test_audio_pool_api.py`：普通、联机、继续游戏、指定存档与其他游戏隔离。
- 前端SettingsModal测试覆盖说明、保存／关闭开关、游戏限制、六种语言和错误翻译；Vite构建检查界面。

游戏内实际分配容量、听感与长时间联机效果由用户完全退出后自行启动游戏验证。启动器日志中的 `instruction_readback_before_initialization` 表示预算指令已核对，不代表已采集游戏内实际占用。本任务不打包或发布新EXE，不更改正式更新清单。
